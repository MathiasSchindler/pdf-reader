A dependency-free PDF renderer for the browser — field notes

pdf-crumb.js

A small experimental PDF renderer that parses objects and content streams directly and paints pages to canvas. It ships as a single minified file, has no runtime dependencies, and is feature-incomplete on purpose.

It is not a replacement for PDF.js. The renderer covers a useful subset of text, paths, fonts, and images — enough to display many real documents — and is honest about what it skips. Built as a learning code base and a development playground, with substantial LLM assistance under human review.

02 Why & when

Useful when small and approximate beats large and exact.

Reach for it when

  • You want to display mostly-text PDFs on a small page without pulling in a multi-megabyte renderer.
  • You want a single script tag that renders a known-good document.
  • You want to read a renderer end-to-end to learn how PDFs work.
  • You need a development playground for parser and rendering experiments.

Don't reach for it when

  • You need to render arbitrary, untrusted, third-party PDFs at production scale.
  • You need exact, legally reliable reproduction (use PDF.js or a server-side renderer).
  • You depend on JPEG 2000, complex masking, transparency groups, or full font shaping.
  • You need form fields, JavaScript, annotations, or interactive features.
03 Use it

One canvas, one script tag.

The default embeddable file is dist/pdf-crumb.viewer.min.js. It keeps stable rendering features — image XObjects, browser-loaded embedded CFF fonts — and leaves diagnostics out.

As an ES module

<canvas id="page"></canvas>
<script type="module">
  import { loadPdfCrumb } from "./dist/pdf-crumb.viewer.min.js";

  const pdf = await loadPdfCrumb("./example.pdf");
  await pdf.renderPage(0, document.getElementById("page"), { scale: 1.5 });
</script>

As a plain script tag

<canvas id="page"></canvas>
<script src="./dist/pdf-crumb.viewer.global.min.js"></script>
<script>
  (async () => {
    const pdf = await PdfCrumb.load("./example.pdf");
    await pdf.renderPage(0, document.getElementById("page"), { scale: 1.5 });
  })();
</script>
04 Builds

Three profiles. Pick the one whose features you actually need.

The build emits each profile as one minified JavaScript file in two flavours — an ESM module and a script-tag global.

viewerdefault
Stable rendering for general PDF display. Image XObjects, browser-loaded embedded CFF fonts, no diagnostics. The right choice for embedding on a third-party page. dist/pdf-crumb.viewer.min.js · .global.min.js
textsmallest
Smallest profile, for text- and vector-only PDFs. Image XObjects are disabled. Use it when you control the input and know it has no rasters. dist/pdf-crumb.text.min.js · .global.min.js
fulldevelopment
Development build with audit data and experimental embedded outline rendering. Used by the local dev reader and comparison tools; not intended for production embedding. dist/pdf-crumb.min.js · .global.min.js
05 Scope

What it does. What it doesn't.

The renderer covers a usefully wide subset of PDF — enough to display many real documents — and stops short of the long tail. The list below is the same one in the README, kept in plain sight on purpose.

Currently useful

  • Direct PDF object parsing and page-tree walking with inherited boxes and rotation.
  • Flate, ASCIIHex, ASCII85, and RunLength stream decoding.
  • Page content stream concatenation and a subset of the operator set.
  • Basic ToUnicode CMap reading.
  • Width tables for simple fonts and Type0/CID descendant fonts.
  • Browser-loaded wrapped Type1C/CFF embedded fonts when accepted by FontFace.
  • Direct outline rendering for safe simple TrueType subsets.
  • Subset of text, path, clipping, form XObject, color, graphics-state, and image XObject operators.
  • JPEG image XObjects via browser image decoding.
  • Raw image XObjects for gray, RGB, ICC-like, CMYK-like, and Indexed data.

Known gaps

  • Full PDF font shaping and all font program formats.
  • JPX / JPEG 2000 and complex masked image XObjects.
  • Full external graphics-state handling.
  • Text clipping modes.
  • Calibrated, ICC, indexed, separation, and pattern color spaces beyond the implemented subset.
  • Advanced clipping interactions and transparency groups.
  • Less common stream filters beyond Flate, ASCIIHex, ASCII85, and RunLength.
  • Annotations, forms, JavaScript, embedded files, and other active content.

If a document doesn't render correctly, that's expected before it's surprising. Open a minimized fixture and check the dev reader's PDF.js comparison view.

06 Security

Bounded by default. Not battle-tested.

The renderer doesn't execute PDF JavaScript, launch files, submit forms, or follow remote actions. Active-content markers (/OpenAction, /JavaScript, /Launch, /SubmitForm, /URI, /EmbeddedFile, /RichMedia, /XFA, …) are reported through pdf.audit().activeContent when diagnostics are on, but never acted on.

Active content
Ignored. Markers are surfaced via pdf.audit(), not executed.
Resource limits
Defaults bound input size, decoded stream bytes, page count, page-tree depth, content operators, graphics stack, form XObject recursion, image dimensions and pixels, embedded font bytes, CMap entries, and object-stream expansion. Tighten via limits.
Cancellation
Pass an AbortSignal to loadPdfCrumb and to renderPage options to cancel parse, fetch, and render work.
Recommended
Run parsing and rendering in a dedicated Worker for untrusted inputs. The in-process limits are still required; the worker is an additional containment layer, not a replacement.
Testing
Local fuzzing harnesses mutate fixture PDFs and feed them to the parser and renderer, with a PDF.js oracle and a deterministic npm run test:security suite. Findings are local robustness bugs until investigated, not exploit reports.
Status
Basic security testing only. Treat the renderer as untested for adversarial production loads.

Constraining a load

import { loadPdfCrumb } from "./dist/pdf-crumb.viewer.min.js";

const controller = new AbortController();
const pdf = await loadPdfCrumb(url, {
  signal: controller.signal,
  limits: {
    maxInputBytes:         32 * 1024 * 1024,
    maxDecodedStreamBytes: 16 * 1024 * 1024,
    maxImagePixels:        8_000_000,
  },
});
